# FormaAI 产品需求（首版）

状态：需求讨论稿。更新日期：2026-11-19。

## 1. 产品目标

FormaAI 支持电商、品牌、知识和故事短视频制作。用户从主题或已有资料开始，确认文字方案与关键帧后生成镜头视频，最后手动合成并下载。制作过程中支持参考图约束、镜头衔接、单镜重做和任务恢复。

首先满足个人同时制作多个视频的需要。提供用户模块，所有任务、分类、资料、资产和服务凭证按用户私有隔离。前端采用 Vue 3，后端采用 FastAPI，数据库采用 MySQL，支持本机和服务器部署。

## 2. 内容范围

| 类型 | 制作入口 | 确认采用后保存的内容 |
|---|---|---|
| 电商 | 从品类探索并选定商品，或直接提供商品资料 | 卖点、产品品类、目标市场及相关依据 |
| 品牌 | 简单目标或已有品牌资料 | 品牌价值与传播重点 |
| 知识 | 主题或已有讲解材料 | 知识要点与讲解逻辑 |
| 故事 | 创意或已有故事文本 | 故事主题与情节方向 |

四种类型分别维护分类。系统根据输入完整度补全方案，每次默认重新制作，只有用户主动选择才复用已有内容。

## 3. 制作流程

完整流程见 [全局业务流程图](global-workflow.md)。

| 阶段 | 系统行为 | 用户操作 |
|---|---|---|
| 创建任务 | 建立独立任务空间，固定初始输入 | 选择类型和分类，提供主题、市场及资料，选择严格使用已有视觉素材或允许 AI 补充 |
| 调研 | 整理资料，联网搜索并获取来源内容 | 资料不足或来源失败时，选择重试、补资料或跳过 |
| 文字方案 | 提炼内容与创作方向，默认生成三版脚本 | 选择一版，确定时长、画幅和分辨率等规格 |
| 脚本确认 | 按最终规格调整候选脚本 | 再次确认，锁定脚本与制作规格 |
| 关键帧 | 提出参考方式和衔接方案，确认后制作关键帧 | 先确认方案，再确认实际关键帧 |
| 镜头视频 | 根据已确认脚本、参考图和配置生成各镜视频 | 预览、单镜重做，选择每镜采用的结果 |
| 合成 | 拼接视频，处理字幕和音频 | 手动触发合成，预览并下载 |
| 结束 | 保留任务和临时产物 | 按需清理临时文件或彻底删除任务 |

关键帧方案由系统提出，可涉及首帧、首尾帧与连续镜头衔接。具体支持方式取决于首版接入服务的能力，服务尚未确定。

音频支持 AI 配音、上传配音、背景音乐和无配音模式。用户不编辑时间线，字幕与音画对齐由系统处理。配音长度与视频时长冲突暂不专项处理，也不因此暂停，具体合成行为待定。

## 4. 修改、重做与恢复

- 点击开始任务后固定品类、市场、主题和初始资料。输出规格在文字方案生成后确定，与最终脚本一起锁定。
- 允许两种任务内修改：调研受阻后补资料或跳过，以及按最终规格调整候选脚本。记录修改和决定，保留已完成阶段。
- 其他上游修改需暂停原任务，创建空任务，再由用户手动选择需要带入的内容。
- 单镜重做允许调整动作、运镜和表现，保持脚本意图、主体、已确认参考图和制作配置不变。保留各次结果供选择。
- 连续镜头的前镜采用新结果后，保留后镜旧结果并标记需要复核，由用户接受或重做。
- 暂停只停止后续工作派发。已提交的外部请求继续跟踪并接收结果，不进入下一阶段。
- 关闭页面或重启服务后可以恢复任务。先核对远端请求及本地产物，避免重复提交。结果缺失且无法获取时，停在对应阶段，由用户确认后重新生成。
- 区分运行、等待确认、暂停、等待重试和最终结束。等待重试不算最终失败。

## 5. 数据与资产

| 保存位置 | 内容 | 保留规则 |
|---|---|---|
| 业务数据库 | 已确认采用的调研、来源、内容提炼、视频特征分析及参考资产记录 | 自动保存，供用户主动选择复用，独立于任务管理 |
| 任务控制记录 | 归属、阶段、确认决定、请求标识、执行尝试、结果引用及已知用量费用 | 支持隔离、追踪、恢复与清理 |
| 任务私有临时存储 | 候选、脚本、关键帧中间结果、镜头视频、音频、字幕及成片 | 跨服务重启保留，直到用户主动清理 |

候选内容不写入长期业务表。分镜脚本和生成视频不设长期业务内容表，数据库可保留必要的任务控制信息及文件引用。可复用的视频分析记录特征、结构拆解和创作方向。

每项资产只属于一个分类，跨分类使用时另存一份。清理任务不能删除已经入库的可复用内容，相关文件需独立保存。

只允许清理已结束任务，包含成功和最终失败。运行、等待重试或暂停中的任务不可清理。提供“仅清理临时文件”和“彻底删除任务”两种操作，清理后的恢复入口应反映实际产物是否存在。

## 6. 账号与权限

- 用户通过邮箱和密码注册，注册时验证邮箱，提供登录与退出登录。
- 用户模块只建立一张用户表。邮件通过第三方邮箱服务商 API 发送，邮箱验证临时数据及限流由 Redis 管理；登录认证采用 JWT + Redis 双 Token（Access Token 与 Refresh Token），不建立邮箱验证表或会话表。
- 管理员可创建、停用、启用和恢复账号。管理员只能查看账号信息、任务状态、资源用量与脱敏错误，不能查看私人内容。
- 停用账号先禁止创建新任务，允许用户处理已有任务，全部结束后完成停用。
- 用户注销时立即终止本地任务流程，将账号标记为逻辑删除，保留业务数据。后台只核对已提交请求的远端状态与费用，不再下载结果。
- 注销邮箱不能重新注册，需管理员恢复原账号。恢复后由用户逐个选择继续未完成的任务，不自动启动。

## 7. AI 与外部服务

每个用户配置自己的服务凭证。首版每种能力接入一个确定服务，覆盖文本、图像、视频、配音、联网搜索及电商数据。任务之间不共享执行上下文，跨用户不能访问凭证或结果。

生成与重做由用户控制，不设置业务预算拦截。记录服务返回的已知用量和费用，未知费用不能记为零。下载或查询失败不能直接触发重新付费生成。

提供用户用量统计，可按日/月、任务、服务商、模型和能力查看消耗及已知费用，并通过执行记录区分重做消耗。费用未知时明确显示未知，不同币种或不同计量单位不直接合计。首版不做钱包、余额和预算系统。

## 8. 首版边界与验收

首版不做共享素材库、团队协作、手动时间线编辑和多供应商自动切换。不自动复用历史内容，不自动重做受影响的后续镜头，也不自动清理临时产物。

验收至少覆盖以下场景：

1. 四种内容类型都能从输入走到合成下载，每个任务只选择一版脚本继续。
2. 脚本、关键帧及合成确认节点生效，未经确认不推进对应制作步骤。
3. 同时运行多个任务不混用输入、文件、事件或生成结果，跨用户访问被拒绝。
4. 单镜重做保留历史结果，连续镜头替换后出现复核提示。
5. 暂停与重启恢复不重复提交已存在的生成请求，缺失结果须确认后再生成。
6. 清理仅作用于允许清理的任务，可复用资料和资产仍可使用。
7. 停用、注销和恢复遵守账号规则，管理员无法读取私人内容。

## 9. 待定事项

- 各能力的服务与模型，以及不支持指定参考方式时的处理流程。
- 更新或删除凭证对未结束任务的影响。
- 调研正文、来源摘录和附件的字段及大小限制。
- 配音时长冲突的合成默认行为，以及关键帧重做与锁定规则的细节。

数据库表结构和接口设计在业务流程确认后展开。
